# ADR-0003: Security & Auto-Mode Policy Engine

- **Status**: accepted
- **Date**: 2026-10-05
- **Deciders**: User, Antigravity Agent

## Context & Problem Statement
Users require an autonomous development experience ("Auto-Mode") where agents can read context from anywhere on the host machine, write implementation files within the project, and run everyday development commands without asking for permission on every single step. At the same time, exposing network ports for mobile access and running automated commands introduces risks of unauthorized access or catastrophic system changes.

## Decision Drivers
- Uninterrupted agent workflow for harmless, standard developer tasks (running tests, reading documentation, making project-local edits).
- Strict containment of file mutations: agent must not overwrite system files or unrelated directories.
- Safe execution: destructive or egress commands must never execute autonomously.
- Secure local network access from mobile devices.

## Considered Options
1. **Option A (Chosen)**: A 3-Tier Security Policy Engine implemented inside the Rust Axum backend with path canonicalization and shell AST parsing, paired with local session tokens and mobile QR pairing.
2. **Option B**: Strict static regex whitelist file (`permissions.json`).
3. **Option C**: Unrestricted shell execution in Auto-Mode without safety prompts.

## Decision Outcome
Chosen option: **Option A**. 
All tool invocations pass through the Rust backend:
- **Filesystem Read**: Allowed anywhere on host via OS read permissions.
- **Filesystem Write**: Path canonicalization (`std::fs::canonicalize`) strictly enforces that destination paths reside within the active project directory (`codebase/<project>/`) or the SDD repository (`specs-repo/<project>/`). Any write attempt outside triggers an immediate security error or interactive prompt.
- **Command Policy**:
  - **Tier 1 (Auto-Allowed)**: Read-only inspection (`git status`, `git diff`, `git log`) and deterministic build/test commands (`cargo test`, `npm test`, `pytest`, `tsc --noEmit`).
  - **Tier 2 (Workspace Mutation)**: Dependency management and local commits (`npm install`, `cargo add`, `git commit`) auto-execute within workspace bounds and record to an undoable audit trail.
  - **Tier 3 (Interactive Gate)**: Egress (`git push`, `npm publish`), destructive actions (`rm -rf`, system reconfigurations), or unparsed scripts pause execution and send a WebSocket approval prompt (`[Approve]` / `[Deny]`) to the UI.
- **Authentication**: Loopback requests on `localhost` auto-authenticate; remote LAN clients (mobile phone) require scanning a one-time QR code or entering a pairing token generated by the CLI.

### Positive Consequences
- Frictionless auto-mode while preventing runaway agent destruction.
- Secure mobile pairing over local Wi-Fi without open LAN vulnerability.
- Immutable audit log of all automated tool calls.
